# 15강 — 풀스택 캡스톤 (초보 시리즈 마무리)

> **위치:** 본 강 전체는 **`lesson-15-fullstack-capstone/강의.md`** 에 있다.  
> **선행:** 1~6강(React)·7~9강(Spring·DB·JWT·메뉴 API) 개념. **11강(Zustand)** 을 안 봐도 따라올 수 있으나, 대비를 위해 읽어 두면 좋다.  
> **JDK·Maven:** **`lesson-07-spring-db-user/강의.md`** 의 「개발 환경 (JDK·Maven)」 절을 참고한다.  
> **Mac + Homebrew:** `brew install maven` 만 했을 때 **`mvn -v`에 Java 25**가 보일 수 있다(의존 JDK). **강의는 17 기준**이므로, 7강 문서의 **「Homebrew로 Maven만 설치했을 때 — JDK 25와 17」**·**「JDK를 17에 맞추고 싶을 때」** 를 읽고 `JAVA_HOME` 을 맞추면 수업과 스크린샷이 일치한다.

---

## 1. 이번 강의에서 배우는 것

- **한 저장소 안에서** PostgreSQL(Docker) → Spring Boot(REST·JWT) → React(Vite) 까지 **끊기지 않게** 실행해 본다.
- **Zustand**로 “브라우저에만 있는 상태”(로그인 토큰, 테마)를 두고, **메뉴 목록**처럼 서버가 갖고 있는 데이터는 **`fetch` + `useState`** 로 다룬다(10강의 TanStack Query 대신 **역할이 보이게** 단순화).
- **CORS**가 왜 필요한지(프론트 출처 `5174`, API `8080`)를 다시 한 번 짚는다.
- **이 강에서 다루지 않는 것(상용 확장)** 을 한눈에 구분한다.

---

## 2. 선행 조건

- Docker(또는 Docker Desktop)로 `docker compose up` 을 실행할 수 있다.
- 터미널에서 `cd`, `npm install`, `npm run dev` 를 쓸 수 있다.
- 백엔드: **Maven** 과 **JDK 17 이상**(문서·`pom.xml` 기준은 **17**).  
  - Mac에서 Homebrew로 Maven을 설치하면 **JDK 25**가 잡혀 **`mvn -v`가 25로 나올 수 있다** — 보통은 그대로 빌드된다. **수업에서는 7과 동일한 17으로 맞추는 것**을 권장한다 → **`lesson-07-spring-db-user/강의.md`** 의 「개발 환경 (JDK·Maven)」 전절, 특히 **JDK 25와 17** 단락.

---

## 3. 왜 마지막에 “캡스톤”인가

7~9강에서는 **API와 DB가 진실**이라는 것을, 10강에서는 **브라우저가 그 API를 부른다**는 것을 배웠다. 11강은 **서버 없이** 클라이언트 상태만 연습했고, 12~14강은 **DB 제품** 관점을 더했다.

15강은 그 줄기들을 **한 번에 겹쳐서 보며** “내가 만든 화면 한 줄이 DB 까지 간다”는 감각을 고정하는 자리다. 페이지 수는 적어도 되지만, **기술 스택의 역할 분담**이 보이게 구성했다.

---

## 4. 새로 등장하거나 다시 짚는 용어

| 용어 | 한 줄 설명 |
|------|------------|
| **세로 슬라이스** | UI → API → DB 한 사용자 시나리오가 끝까지 닿는 단위. |
| **JWT** | 로그인 성공 후 받는 문자열. 이후 요청에 `Authorization: Bearer ...` 로 실어 보낸다. |
| **CORS** | 브라우저가 “다른 출처”의 API를 부를 때 서버가 허용해 주는 규칙. |
| **Zustand persist** | 스토어 일부를 `localStorage` 등에 저장해 새로고침 후에도 남기는 미들웨어(11강과 동일 계열). |

## 5. 이 강의 폴더 구조

```
lesson-15-fullstack-capstone/
  docker-compose.yml     ← PostgreSQL (호스트 포트 5438)
  backend/               ← Spring Boot (기본 8080)
  frontend/              ← Vite React (개발 서버 5174)
  강의.md
  README.md
```

### 5-1. 백엔드(`backend/`) — Maven 컴파일 **전**과 **후**

7~13강은 **저장소 루트가 곧 Maven 프로젝트**이고, 15강은 그 역할이 **`backend/`** 안에 있다. **내용은 같다**: 처음에는 `pom.xml` 과 `src/` 만 있고, **`mvn` 을 돌리기 전에는 `target/` 이 없는 것이 정상**이다(저장소 **루트** `.gitignore` 가 `target/` 을 제외한다).

| 시점 | 보이는 것(요지) |
|------|----------------|
| **컴파일 전** | `backend/pom.xml`, `backend/src/main/...` — **`backend/target/` 없음** |
| **`mvn compile` 등 실행 후** | 위에 더해 **`backend/target/classes/`** 등 Maven 산출물 |

상세한 트리 예시·`mvn clean` 설명은 **`lesson-07-spring-db-user/강의.md`** 의 「개발 환경 (JDK·Maven)」 안 **「Maven 컴파일 전과 후 폴더 모습」** 절을 본다(8~15강 공통).

## 6. 따라 하기 (순서대로)

### 6-1. PostgreSQL 기동

터미널에서:

```bash
cd lesson-15-fullstack-capstone
docker compose up -d
```

- DB 이름: `beanlog_lesson15`, 사용자/비밀번호: `beanlog` / `beanlog` (개발용 예시).
- **호스트 포트 5438** — 12~14강 Postgres 와 동시에 띄워도 충돌하지 않게 했다.

### 6-2. 백엔드 실행

```bash
cd backend
mvn spring-boot:run
```

- 위 명령은 내부적으로 컴파일도 수행하므로, **첫 실행 후**에는 `backend/target/` 이 생긴다(§5-1·7강 문서 참고).
- (선택) 컴파일만 먼저 확인하려면 같은 디렉터리에서 `mvn -DskipTests compile` 을 실행해 본다.

- 첫 기동 시 JPA 가 테이블을 만들고(`ddl-auto: update`), 시드가 **관리자 계정**과 **예시 메뉴 2건**을 넣는다.
- **시드 관리자 (로그인용)**  
  - 아이디: `admin`  
  - 비밀번호: `admin1234`  
  - (운영에서는 절대 이렇게 두지 않는다.)

동작 확인(선택):

```bash
curl -s http://localhost:8080/api/health
curl -s http://localhost:8080/api/menus
```

### 6-3. 프론트엔드 실행

**새 터미널**에서:

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 **`http://localhost:5174`** 로 연다(10강은 5173 이므로 **동시에 띄울 수 있다**).

API 주소는 기본값으로 `http://localhost:8080` 을 쓴다. 바꾸려면 `frontend/.env.example` 을 참고해 `frontend/.env` 를 만들고 `VITE_API_BASE_URL=...` 을 적는다.

### 6-4. 화면에서 확인할 것

1. **메뉴판(홈)** — 로그인 없이 공개 `GET /api/menus` 결과가 보인다.  
2. **로그인** — 시드 계정으로 로그인하면 Zustand 에 토큰이 저장된다.  
3. **관리** — 토큰이 있어야 들어갈 수 있다. 메뉴 추가·삭제가 DB 에 반영된다.  
4. **테마 전환** — Zustand 로만 바뀌는 UI 상태(서버와 무관).

## 8. 설계 메모 (초보자가 헷갈리기 쉬운 점)

### 8-1. 왜 메뉴 목록은 Zustand 에 안 넣었나

**서버가 진실(source of truth)** 인 데이터를 전역 스토어에 복제해 두면, 추가·삭제 후 **동기화**를 또 신경 써야 한다. 10강에서는 TanStack Query 가 그 부담을 줄여 준다.

15강에서는 **“토큰·테마 = 클라이언트”**, **메뉴 = 서버에서 매번 가져오기**로 나누어, 11강에서 말한 **역할 분리**를 유지했다.

### 8-2. 10강과의 차이

| 항목 | 10강 | 15강 |
|------|------|------|
| 서버 상태 캐시 | TanStack Query | `useState` + 수동 새로고침 |
| 토큰 저장 | `sessionStorage` 등 | Zustand **persist** |
| API | 9강 서버 연동 | **이 폴더의 백엔드** (5438 DB) |

### 8-3. 14강(HikariCP)과의 연결

백엔드가 DB 에 붙을 때 연결 **풀**로 HikariCP 를 쓴다는 설명은 **14강 `application-hikari.example.yml`** 과 같은 맥락이다. 15강 백엔드는 `application.yml` 의 `spring.datasource` 로 그 설정을 받는다.

## 9. 이 강의가 일부러 넣지 않는 것 (다음 단계)

- **배포**(클라우드·도메인·HTTPS·환경별 설정)

이들은 입문 후 공식 문서·실무 가이드를 따라가면 된다.

## 10. 막혔을 때

| 증상 | 확인 |
|------|------|
| `Connection refused` (프론트에서 API) | 백엔드가 8080 에 떠 있는지, `VITE_API_BASE_URL` 이 맞는지 |
| CORS 에러 | 프론트가 `http://localhost:5174` 인지, 백엔드 `SecurityConfig` 의 허용 출처 |
| 로그인은 되는데 관리 메뉴가 403 | 토큰이 요청에 붙었는지, 시드 계정이 `ROLE_ADMIN` 인지 |
| Postgres 연결 실패 | `docker compose ps`, 포트 **5438**, DB 이름 `beanlog_lesson15` |
| **`mvn -v`에 Java 25, 강의는 17** | 정상일 수 있음(Maven이 그 JDK를 씀). **7강** 「개발 환경」의 **JDK 25와 17**·**JAVA_HOME** 절로 17에 맞추거나, 맞추지 않아도 **`mvn compile` 성공**이면 진행 가능 |

- [ ] 메뉴를 하나 추가한 뒤, DB 클라이언트나 `curl` 로 `GET /api/menus` 가 바뀌었는지 확인한다.
- [ ] `useAuthStore` 와 `useUiStore` 중 무엇이 “서버와 무관한지” 한 문장으로 쓴다.

## 12. 시리즈를 마치며

이 시리즈는 **작은 웹사이트를 만든다**는 목표에서 출발해, **데이터가 DB 에 남고**, **API 가 규칙을 지키고**, **브라우저가 그 위에서 동작한다**는 흐름까지 왔다.

15강은 그 흐름을 **한 폴더**에 모아 두었을 뿐, 배우는 사람의 앞에는 여전히 넓은 길이 있다. 여기서 멈추지 말고, **한 가지 기능**을 스스로 추가해 보면(예: 메뉴 수정 `PUT`, 검색 필드) 그때부터는 “읽는 강의”가 아니라 **당신의 프로젝트**가 된다.

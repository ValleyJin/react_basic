## 1. 이번 강의에서 배우는 것

- **중앙 HTTP 레이어** (`src/api/httpClient.js`): 베이스 URL·JSON·`Authorization: Bearer` 를 한곳에서 처리(axios 인터셉터에 해당하는 역할을 교육용으로 단순화).
- **TanStack Query**: 메뉴 목록처럼 **서버에서 오는 데이터**는 **서버 상태**로 보고 `useQuery` / `useMutation` 으로 가져오고, 변경 후에는 **캐시 무효화**로 화면과 서버를 맞춘다.
- **`react-router-dom`**: `/`, `/login`, `/admin/menus` 라우팅과 **보호 라우트**(토큰 없으면 로그인으로).
- **6강과의 연결**: “조립은 앱 진입점에서” — `main.jsx`의 `QueryClientProvider` + `BrowserRouter`. 화면은 `menuApi`·쿼리 훅만 사용.

## 3. 7~9강과 10강의 역할

| 단계 | 백엔드(요약) | 10강(React)에서 하는 일 |
|------|----------------|-------------------------|
| 7~8 | DB·사용자·JWT 발급 | 이미 만들어진 로그인 API를 **호출**해 토큰을 받는다 |

## 4. 서버 상태를 TanStack Query로 다루는 이유 (요약)

- `useEffect` 안에서 `fetch`만 써도 동작은 한다. 다만 **로딩·에러·중복 요청·갱신 타이밍**을 페이지마다 반복 작성하기 쉽다.
- TanStack Query는 **같은 `queryKey`를 공유하는 데이터**를 한곳에서 캐시하고, `invalidateQueries`로 “이제 다시 가져와”를 선언할 수 있다.
- 10강에서는 **메뉴 목록**이 홈(`/`)과 관리자(`/admin/menus`)에서 **같은 키**로 맞춰져, 한쪽에서 추가·삭제하면 **무효화 후** 다른 쪽도 갱신될 수 있다.

---

## 5. 로그인부터 API 호출까지 (흐름)

1. 사용자가 `/login`에서 아이디·비밀번호 제출.
2. `useMutation`이 `authApi.loginRequest` → `httpClient.request('/api/auth/login', …)` 호출 (이때는 아직 Bearer 없음).
3. 응답 JSON의 `accessToken`을 `sessionStorage`에 저장(`httpClient`의 `setToken`).
4. 이후 `request()`는 같은 저장소에서 토큰을 읽어 `Authorization: Bearer …` 를 붙인다.
5. 관리자 메뉴에서 `POST/DELETE` 성공 시 `invalidateQueries({ queryKey: menuKeys.all })` 로 목록 쿼리를 다시 불러오게 한다.

**보호 라우트**(`ProtectedRoute`)는 “토큰이 없으면 로그인으로 보낸다”는 **클라이언트 측 편의**이며, 서버는 여전히 JWT로 권한을 검사한다.

---

## 6. 9강 API와의 대응 (복습)

| 메서드 | 경로 | 10강에서 |
|--------|------|----------|
| POST | `/api/auth/login` | `LoginPage` → `loginRequest` |
| GET | `/api/menus` | `HomePage`·`AdminMenusPage` → `menuApi.list` (`useQuery`) |
| POST | `/api/menus` | 관리자 → `menuApi.create` (`useMutation`) |
| DELETE | `/api/menus/:id` | 관리자 → `menuApi.remove` (`useMutation`) |

베이스 URL은 `.env.development`의 `VITE_API_BASE`(기본 `http://localhost:8080`)이다.

---

## 7. 새로 등장하는 용어

| 용어 | 설명 |
|------|------|
| **서버 상태** | API 응답으로 결정되는 데이터. Query가 캐시·재요청을 돕는다. |
| **queryKey** | 같은 키 = 같은 캐시 줄. `menuKeys.list()` / `invalidateQueries({ queryKey: menuKeys.all })` 로 묶는다. |
| **보호 라우트** | 토큰 유무로 화면 접근을 막음(서버의 401/403과 별개인 UX). |
| **Mutation** | 서버에 **쓰기**할 때 쓰는 Query의 훅(`useMutation`). 로그인·추가·삭제에 사용. |

## 8. 코드 읽는 순서 (추천)

1. `src/api/httpClient.js` — 모든 요청이 거치는 공통 진입점.
2. `src/api/menuApi.js`, `authApi.js` — 경로·메서드만 모아 둔 얇은 레이어.
3. `src/api/queryKeys.js` — 캐시 키 상수.
4. `src/query/queryClient.js` — `staleTime` 등 기본 옵션.
5. `src/main.jsx` — `QueryClientProvider` + `BrowserRouter`.
6. `src/pages/HomePage.jsx` — 공개 `useQuery`.
7. `src/pages/LoginPage.jsx` — `useMutation` 로 로그인.
8. `src/pages/AdminMenusPage.jsx` — `useQuery` + `useMutation` + 무효화.
9. `src/components/ProtectedRoute.jsx` — 토큰 검사.

## 11. 막혔을 때

## 13. 정리 및 다음 단계

이 시리즈(07~10)는 **DB → 인증 → 도메인 API → UI** 로 이어진다. 10강은 **얇은 HTTP + TanStack Query** 로 **서버 상태**를 다루는 실무에 가까운 패턴을 연습한다.

**선택 확장:** 테마·손님 장바구니처럼 **브라우저 안에서만** 의미 있는 전역 상태는 **`lesson-11-zustand-client-state`** 의 **`강의.md`** 와 코드에서 **서버 상태와의 구분**을 이어 볼 수 있다.

**시리즈 마무리(선택):** 같은 BeanLog 메뉴 도메인을 **한 레포에서** DB → API → React까지 한 번에 엮어 보려면 **`lesson-15-fullstack-capstone/강의.md`** 를 본다. 15강은 **자체 `backend/`·Postgres(5438)·프론트(5174)** 를 쓰고, 프론트는 TanStack Query 대신 **Zustand + `fetch`** 로 단순화해 두었으므로 **10강과는 별도 실행**으로 이해하면 된다(루트 **`README.md`** 의 10강·15강 비교 표).

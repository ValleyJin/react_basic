# BeanLog 확장 — 백엔드·관리자 시리즈 기획 (lesson-07 ~ )

6강까지는 **브라우저 + (필요 시) localStorage** 수준입니다. 여기서는 **Spring Boot + PostgreSQL**로 넘어가 **관리자 로그인**과 **메뉴 CRUD**를 다룹니다.

아래는 **한 강에 모두 넣지 않고**, 초보자가 따라오기 쉽게 **4개 강의로 쪼갠 권장안**과, 각 강의에 넣을 **설명 순서·강의.md 골격**입니다.  
실제 폴더(`lesson-07-...`)를 만들 때 이 문서를 **단일 기준**으로 삼으면 됩니다.

---

## 1. 왜 4강(07~10)으로 나누는가

| 기준 | 설명 |
|------|------|
| **인지 부담** | Spring 설정·DB·보안·CORS·React 연동을 한 번에 넣으면, 오류가 나도 “어디가 원인인지” 분리하기 어렵다. |
| **검증 가능한 중간 결과** | 각 강 끝에서 “여기까지는 동작 확인”을 하게 하면 성취감과 디버깅 습관이 생긴다. |
| **역할 분리** | 먼저 **API·DB가 진실**이 되게 하고, 그다음 **화면이 API를 부른다**는 순서가 읽기 쉽다. |

3강으로 줄이면 중간 검증이 부족해지고, 5강 이상으로 쪼개면 “언제 끝나나” 부담이 커질 수 있다. **4강**이 교육용으로 균형이 잡힌 편이다.

## 2. 강의별 범위 (권장)

### lesson-07 — 백엔드 뼈대 + DB + “사용자” 저장

**구현 폴더:** `lesson-07-spring-db-user` (코드·`강의.md`·`docker-compose.yml` 포함)

**개발 환경:** JDK·Maven 설치 확인·버전 맞추기는 해당 폴더 **`강의.md`** 의 **「개발 환경 (JDK·Maven)」** 절에 두고, 8~13·15강 백엔드에서 **같은 절을 참고**하면 된다.

**한 줄 목표:** PostgreSQL에 연결된 Spring Boot 앱이 뜨고, **사용자(User)** 정보를 테이블에 넣고 읽을 수 있다.

**포함할 것 (예시)**

- Spring Boot 프로젝트 생성, `application.yml`에 Postgres 접속 정보(환경 변수 권장).
- JPA 엔티티 `User`(id, username, passwordHash, role 등 최소 필드).
- 비밀번호는 **평문 저장 금지** — BCrypt로 해시만 저장한다는 것을 강의에서 명시.
- (선택) 초기 관리자 1명을 **시드**하거나, 공개용 `POST /api/register` 하나만 두고 Postman으로 한 명 생성.

**일부러 넣지 않을 것**

- React, JWT 전체 흐름(다음 강으로 미룸).
- 메뉴 도메인(08 또는 09로).

**끝나면 학습자가 할 수 있는 것**

- DB 클라이언트나 앱 로그로 “행이 생겼다”를 확인한다.

---

### lesson-08 — 인증 API (로그인) + Spring Security 개요

**구현 폴더:** `lesson-08-spring-security-jwt` (코드·`강의.md`·`docker-compose.yml` 포함)

**한 줄 목표:** 아이디/비밀번호로 **로그인 요청 시 성공/실패**가 나가고, 이후 요청에 **“로그인된 관리자”임을 구분**할 수 있다.

**포함할 것 (예시)**

- 로그인 엔드포인트(예: `POST /api/auth/login`) — 요청 본문에 username/password.
- 응답에 **JWT** 또는 **세션 쿠키** 중 **하나만** 선택해 일관되게 설명(초보 과정에서는 JWT가 SPA와 맞추기 쉬운 경우가 많음).
- 비밀번호 검증: 저장된 해시와 `BCrypt.matches`.
- 관리자 전용 URL에 `@PreAuthorize` 또는 Security 설정으로 **ROLE_ADMIN**만 허용하는 **테스트용 엔드포인트** 하나(예: `GET /api/admin/ping`).

**일부러 넣지 않을 것**

- React (아직). Postman/curl로만 검증.
- 메뉴 CRUD.

**끝나면 학습자가 할 수 있는 것**

- 토큰/쿠키를 붙여서 관리자 전용 API와 그렇지 않은 API를 구분해 본다.

---

### lesson-09 — 메뉴 도메인 API (CRUD) + 권한

**구현 폴더:** `lesson-09-spring-menu-crud` (코드·`강의.md`·`docker-compose.yml` 포함)

**한 줄 목표:** **Menu**를 Postgres에 두고, **공개 읽기(`GET`)**와 **관리자 전용 쓰기(`POST`/`PUT`/`DELETE`)**를 분리한 REST API를 완성한다(CORS 포함).

**포함할 것 (예시)**

- 엔티티 `Menu`(id, name, price, … 5~6강 도메인과 맞추기).
- `GET/POST/PUT/DELETE` 중 강의에서 선택한 스타일(실무에 가깝게 `REST` 명명).
- 모든 쓰기 작업은 **관리자 인증 필수**.
- (선택) 공개용 `GET /api/menus`는 읽기만 허용 — 나중에 일반 사용자용 프론트와 연결하기 좋다.

**프론트**

- 여전히 **선택**: Postman으로만 끝내도 되고, **아주 얇은** `fetch` 스크립트 한 파일만 추가해도 된다. 다만 초보자면 **09는 API 검증에 집중**하는 편이 낫다.

**끝나면 학습자가 할 수 있는 것**

- DB에 메뉴가 쌓이고, 비관리자 토큰으로는 막힌다는 것을 직접 확인한다.

---

### lesson-10 — React 관리자 화면: 로그인 + 메뉴 관리 UI

**구현 폴더:** `lesson-10-react-admin-ui` (Vite·`강의.md` 포함, 9강 API와 연동)

**한 줄 목표:** Vite React로 **관리자 로그인 페이지**, **로그인 후에만 보이는 관리자 경로**, **메뉴 목록·추가·삭제**(및 필요 시 수정)를 붙인다.

**포함할 것 (예시)**

- CORS 설정(개발: React origin 허용). 프론트는 **중앙 HTTP 레이어**(베이스 URL·공통 헤더·JSON) + **TanStack Query**로 서버 상태를 다루고, 로그인 후 토큰은 `sessionStorage` 등에 저장(`memory` vs `sessionStorage` 트레이드오프 한 단락).
- 라우터에서 **보호된 라우트**(미로그인 시 로그인으로).
- 메뉴 목록 로딩/에러/빈 목록을 Query의 `useQuery`/`useMutation` 패턴으로 표시.
- 6강 IoC와 연결: 조립 루트(`QueryClientProvider` + HTTP 규칙)와 화면 분리 — **6강 `강의.md` 8절**(요약) 및 **`lesson-10-react-admin-ui/강의.md`**(본문).

**일부러 넣지 않을 것 (첫 버전)**

- 소셜 로그인, 리프레시 토큰, 비밀번호 찾기 등.

**끝나면 학습자가 할 수 있는 것**

- 브라우저만으로 관리자 로그인 후 메뉴를 CRUD하고, 새로고침·재접속 시나리오를 스스로 점검한다.

## 3. 설명 순서를 이렇게 잡는 이유 (교육 원칙)

1. **진실의 원천을 먼저**  
   DB와 API가 먼저 이해되어야 “화면이 왜 이런 데이터를 보여주나”가 납득된다.

2. **한 번에 하나의 ‘새 축’**  
   07=인프라+엔티티, 08=인증, 09=도메인 CRUD, 10=UI. 겹치면 디버깅이 지옥이 된다.

3. **각 강 끝에 ‘검증 절차’ 고정**  
   강의.md마다 “이걸 하면 성공” 체크리스트를 동일한 위치에 둔다.

4. **보안은 ‘나중에 꾸미기’가 아니라 매 강 한 줄**  
   평문 비밀번호, `.env` 커밋 금지, 프로덕션 CORS 등 **한 줄씩이라도 반복**한다.

5. **React 시리즈(1~6)와 어휘 연결**  
   state/props, `useEffect`, 라우터, 6강 Context·주입 등을 **“이제 서버가 단일 진실”**로 바뀌었다고 짧게 연결한다.

## 10. (선택) lesson-15 — 풀스택 캡스톤 (시리즈 마무리)

**구현 폴더:** `lesson-15-fullstack-capstone` — 루트에 `docker-compose.yml`, 하위에 `backend/`(Maven·Spring Boot)·`frontend/`(Vite·React).

**한 줄 목표:** 초보 트랙을 따라 온 학습자가 **DB → API → 브라우저**가 한 흐름으로 연결된 그림을 한 번에 확인한다.

**포함할 것 (요지)**

- PostgreSQL(Docker, 호스트 포트 **5438** — 12~14와 분리).
- Spring Boot: JPA·JWT·메뉴 REST(7~9강과 동일한 도메인 스토리).
- React: **Zustand**로 로그인 토큰·테마 등 **클라이언트 상태**, `fetch` 로 API 호출(10강의 TanStack Query 대신 단순화해 “한 강에 무엇이 있는지”가 보이게).
- 프론트 개발 서버 포트 **5174**(10강 `5173` 과 동시 실행 가능).

**일부러 넣지 않을 것 (범위 밖)**

- 운영 배포(Kubernetes, CDN), 관측(APM), E2E 테스트, 리프레시 토큰·소셜 로그인 등 — **한 줄로 “다음에 읽을 것”**만 `강의.md` 에 둔다.

**상세 목차·실행 순서·코드 지도:** **`lesson-15-fullstack-capstone/강의.md`**

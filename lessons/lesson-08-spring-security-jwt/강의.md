# 8강 — 인증 API(JWT) + Spring Security

## 이번 강의에서 배우는 것

- **Spring Security**로 URL별 접근 제어
- **JWT(JSON Web Token)**: 로그인 성공 후 클라이언트가 들고 다니는 문자열(이 강의는 HS256 대칭키)
- **`Authorization: Bearer …`** 헤더로 이후 요청에 인증 정보 전달
- **`@PreAuthorize`** 로 메서드 단위 권한(관리자)

## PostgreSQL·연동 (7강 복습)

- 데이터는 여전히 **PostgreSQL**에 있으며, 접속 정보는 `src/main/resources/application.yml` 의 `spring.datasource` 이다.
- 이 프로젝트는 Docker Compose로 띄운 DB에 맞춰 **호스트 포트가 5433** 이다(7강은 5432). `jdbc:postgresql://localhost:5433/beanlog_lesson08` 형태로 Spring이 JDBC에 연결한다.
- **JPA**(`ddl-auto: update`)로 스키마가 갱신되고, **로그인 검증**은 `User` 테이블에 저장된 **BCrypt 해시**와 요청의 평문 비밀번호를 비교하는 흐름이다(7강 시드와 연결).
- PostgreSQL **SQL 문법·역할 관리**까지는 이 시리즈에서 깊게 다루지 않는다. 여기서는 **“스프링이 JDBC로 붙는다”** 수준에 집중한다.

## 7강과의 차이

| 7강 | 8강 |
|-----|-----|
| `/api/users` 누구나 | **JWT + ROLE_ADMIN** 필요 |
| Security 없음 | **필터 체인 + JWT 필터** |

## 새로 등장하는 용어

| 용어 | 설명 |
|------|------|
| **JWT** | 헤더·페이로드·서명으로 이루어진 토큰. 서버가 비밀키로 서명해 위조를 어렵게 한다(교육용 단순화). |
| **Stateless** | 서버가 세션 저장소에 로그인 상태를 안 두고, 매 요청마다 토큰으로 검증한다. |
| **hasRole('ADMIN')** | 스프링이 내부적으로 `ROLE_ADMIN` 권한과 매칭한다. |

## 코드 지도

| 경로 | 역할 |
|------|------|
| `security/SecurityConfig.java` | 어떤 URL을 열고 막을지, CSRF 끄기, 세션 없음 |
| `security/JwtService.java` | 토큰 발급·검증 |
| `security/JwtAuthenticationFilter.java` | 매 요청마다 Bearer 토큰 파싱 → `SecurityContext` |
| `web/AuthController.java` | 로그인, BCrypt 검증 후 JWT 발급 |

## 환경 (Maven)

- 이 프로젝트는 **JDK 17**과 **Maven**(`mvn`)을 가정한다.
- 코드가 컴파일되는지만 빠르게 보려면 프로젝트 루트에서 **`mvn -DskipTests package`** 를 실행한다(테스트는 건너뜀).
- 앱을 실제로 띄울 때는 아래 **따라 하기**처럼 `mvn spring-boot:run` 을 쓴다.

## 따라 하기

1. Docker로 Postgres 기동 후 `mvn spring-boot:run`
2. Postman에서 `POST /api/auth/login` — Body raw JSON
3. `accessToken`으로 `GET /api/admin/ping` — Headers에 Bearer 추가
4. 토큰 없이 `/api/users` 호출 → 401/403 확인

## 막혔을 때

| 증상 | 확인 |
|------|------|
| 403 Forbidden | `ROLE_ADMIN`이 JWT에 들어갔는지, 필터가 먼저 실행되는지 |
| 401 | 토큰 만료·서명 불일치·헤더 형식 |

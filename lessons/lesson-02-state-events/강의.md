# 2강 — 상태(`useState`)와 이벤트(클릭)

## 이번 강의에서 배우는 것

- **`useState`**: 컴포넌트 안에서 바뀔 수 있는 값(상태)을 만든다
- **이벤트 핸들러**: `onClick={() => ...}`처럼 사용자 행동에 반응한다
- **리렌더**: 상태가 바뀌면 React가 해당 컴포넌트를 다시 그린다
- **조건부 렌더링**: `&&`, 삼항 연산자로 “보일 때/안 보일 때”를 나눈다
- **자식은 클릭만, 부모가 상태를 갱신**(콜백 props): 업데이트의 “주체”를 부모에 두는 패턴의 시작

## 1강과 무엇이 달라졌나?

1강은 화면이 항상 같았습니다(정적).  
2강부터는 **같은 컴포넌트라도 상태에 따라 화면이 달라집니다.**

## `useState`의 기본 형태

```js
const [value, setValue] = useState(초기값)
```

- `value`: 현재 상태
- `setValue`: 상태를 바꿀 때 쓰는 함수
- 상태를 바꿀 때는 **새 값**을 넣거나, **`이전 값 => 다음 값`** 형태로 갱신할 수 있습니다(카운터에서 흔함)

## 왜 `onClick`에 함수를 넘기나?

- `onClick={handleClick}`: 함수를 “등록”합니다(호출 결과를 넣는 게 아님)
- `onClick={() => setVisitCount(n => n + 1)}`: 짧게 쓰기 좋은 형태입니다

## 이 예제가 말해주는 “데이터 흐름”

- `MenuCard`는 버튼을 렌더링하지만, **어떤 메뉴가 선택됐는지**는 `App`의 `selectedId`가 기억합니다.
- 자식은 `onSelect` 콜백을 호출할 뿐이고, 실제 `setSelectedId`는 부모가 소유합니다.

이 패턴은 3강의 **state 끌어올리기**로 자연스럽게 이어집니다.

# 14강 — PostgreSQL 운영 맛보기 (스타일 C: 백업 · 연결 풀 · 볼륨)

> **위치:** 본 강 전체는 **`lesson-14-postgresql-ops/강의.md`** 에 있다.  
> **선행:** 12강(`psql`)·Docker Compose 경험.  
> **이 폴더에는 Spring Boot 실행 파일이 없다** — `application-hikari.example.yml` 은 7~13강 프로젝트에 **복사해 참고**하는 용도다.

---

## 1. 이번 강의에서 배우는 것

- **`pg_dump`** 로 DB를 **논리 백업**(SQL 텍스트)하는 기본
- **`docker exec`** 로 컨테이너 안의 도구를 호출하는 패턴
- **Docker named volume** 이 데이터 디렉터리를 유지한다는 점(컨테이너를 지워도 볼륨은 남을 수 있음)
- Spring Boot 기본 **HikariCP** 풀 옵션을 **어디에 적는지**(예시 YAML)
- (참고) 물리 백업·복제·클러스터는 **범위 밖** — 입문 후 공식 문서로 확장

---

## 2. 스타일 C가 다루는 경계

## 3. 준비

```bash
cd lesson-14-postgresql-ops
docker compose up -d
psql "postgresql://beanlog:beanlog@localhost:5437/beanlog_lesson14" -f sql/01_seed.sql
```

포트 **5437** — 12~13강과 충돌하지 않게 분리했다.

---

## 4. 백업 스크립트 (`scripts/pg_dump_plain.sh`)

- 컨테이너 이름 `beanlog-lesson14-postgres` 에 대해 `pg_dump` 실행
- 결과는 `./backups/*.sql` (기본 폴더, 인자로 변경 가능)
- **실행 전:** `chmod +x scripts/pg_dump_plain.sh`

운영에서는 파일을 S3·오브젝트 스토어로 옮기고, 접근 권한을 제한한다 — 여기서는 생략.

---

## 5. 복원 (`scripts/pg_restore_plain.sh`)

- **주의:** 같은 DB에 스키마가 이미 있으면 충돌할 수 있다. 학습용으로 **새 DB**에 넣거나, 테스트 전에 DB를 비운다.
- 사용 예: `./scripts/pg_restore_plain.sh ./backups/beanlog_lesson14_YYYYMMDD.sql`

`pg_dump` / `pg_restore` 의 **커스텀 포맷(-Fc)** 은 14강 범위를 넓히지 않고, **평문 SQL** 위주로 두었다. 필요하면 PostgreSQL 문서 “pg_dump” 절을 본다.

---

## 6. HikariCP 예시 (`application-hikari.example.yml`)

- Spring Boot는 기본적으로 **HikariCP**를 쓴다.
- `maximum-pool-size`, `connection-timeout` 등은 **트래픽·DB 제한**에 맞춰 조정한다.
- 이 파일은 **복사용**이며, 7·9·13강 등 실제 `application.yml` 의 `spring.datasource` 아래에 합칠 때 참고한다.

**JPA와의 관계:** `spring-boot-starter-data-jpa` 를 쓰는 7~9강이든, JPA 없이 `JdbcTemplate` 만 쓰는 13강이든, DB에 붙는 건 **같은 `DataSource`**(기본 구현이 HikariCP)이다. 그래서 **연결 풀 옵션은 `spring.datasource` + `spring.datasource.hikari.*`** 에 두며, **JPA 전용으로 따로 풀을 새로 만드는 것이 아니다** — 14강에 JPA 코드를 넣지 않아도, 9강 프로젝트의 `application.yml` 에 위 예시 블록을 **합치면** 그대로 적용된다는 뜻이다.

---

## 7. Docker 볼륨과 데이터 지속성

`docker-compose.yml` 의 `lesson14_pgdata` 볼륨은 Postgres 데이터 디렉터리를 담는다.  
`docker compose down` 만 하면 볼륨은 기본적으로 남는다(삭제하려면 `-v` 등 명시적 옵션 필요).  
**백업**은 이런 볼륨을 통째로 복사하는 방식과, **`pg_dump` 논리 백업** 방식이 모두 존재한다 — 용도가 다르다.

## 8. 막혔을 때

| 증상 | 확인 |
|------|------|
| `docker exec` 실패 | 컨테이너 이름·실행 중 여부(`docker ps`) |
| 덤프가 비어 있음 | 리다이렉션 권한, 디스크 용량 |
| 복원 시 권한/소유자 오류 | `--no-owner` 등 덤프 옵션(스크립트에 일부 반영됨) |

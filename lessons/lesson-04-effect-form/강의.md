# 4강 — `useEffect`(부수 효과)와 제어 컴포넌트 폼

## 이번 강의에서 배우는 것

- **`useEffect`**: 렌더링 “이후에” 실행되는 코드를 둔다(저장, 구독, 동기화 등)
- **의존성 배열 `[menuItems]`**: `menuItems`가 바뀔 때만 이 effect가 다시 실행된다
- **`localStorage`**: 새로고침 후에도 남는 간단 저장소(교육/프로토타입에 자주 등장)
- **제어 컴포넌트**: `<input value={state} onChange={...} />`처럼 입력값을 state가 주도한다
- **유효성 검사**: 제출 시점에 사용자에게 피드백(에러 메시지)

## `useEffect`를 언제 쓰나?

React 컴포넌트의 본문은 “화면을 계산”하는 곳에 가깝습니다.  
그래서 다음 같은 작업은 보통 effect로 분리합니다.

- 브라우저 저장소에 쓰기/읽기(주의: 초기 로드 전략은 여러 가지가 있음)
- 타이머/구독/네트워크 요청(이 강의는 네트워크를 생략)

## 이 예제의 저장 전략(교육용 단순화)

- 초기 state는 `useState(() => loadItemsFromStorage())`로 **첫 렌더 전에** 읽습니다.
- 이후 변경은 `useEffect`로 `localStorage`에 **JSON 문자열**로 저장합니다.

> 실무에서는 저장 타이밍(디바운스), 스키마 버전 관리, 오류 처리 등을 더 정교하게 합니다.

## 데이터베이스(서버) 없이 어떻게 “유지”되나?

이 예제는 **원격 DB나 API와 연동하지 않습니다.**  
메뉴 데이터는 브라우저가 제공하는 **`localStorage`**에 **JSON 문자열**로 저장하고, 새로고침할 때 같은 브라우저에서 다시 읽어 옵니다.

- **의미상:** “웹앱 ↔ 브라우저 저장소”에 가깝고, **서버·데이터베이스와의 동기화**는 아닙니다.
- **한계:** 같은 PC의 다른 브라우저 프로필·다른 기기와는 자동으로 공유되지 않으며, 사용자가 저장소를 비우면 사라집니다.  
  나중에 **백엔드 API + DB**를 두면, 같은 역할을 `fetch`로 서버와 주고받도록 바꾸는 식으로 확장합니다.

## 제어 컴포넌트가 익숙해지는 포인트

- 입력창의 값은 `value`로 고정되고, 사용자가 타이핑하면 `onChange`가 state를 바꾼다
- “빈 값으로 초기화” 같은 것도 state만 바꾸면 UI가 따라온다

## 자습 체크리스트

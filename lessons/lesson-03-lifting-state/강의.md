# 3강 — 리스트 렌더링(`map`)과 state 끌어올리기

## 이번 강의에서 배우는 것

- **배열 상태**: 메뉴 목록처럼 “여러 개의 데이터”를 하나의 state로 관리
- **`map`으로 리스트 렌더링**: 같은 UI를 데이터 길이만큼 반복
- **`key`**: 리스트 항목을 안정적으로 식별(보통 DB id 또는 고유 id)
- **state 끌어올리기**: 형제 컴포넌트가 같은 데이터를 써야 하면, 그 데이터를 **공통 부모**로 올린다
- **제어의 역전(느낌)**: 화면 컴포넌트는 props/콜백으로 “주입”받고, 갱신 책임은 데이터 소유자가 가진다

## 왜 `key`가 필요한가?

React는 UI를 “데이터가 어떤 항목인지” 추적해야 효율적으로 업데이트할 수 있습니다.  
특히 리스트에서 항목이 추가/삭제/정렬될 때, `key`가 흔들리면 상태가 엉키는 문제가 생길 수 있습니다.

- **권장**: 항목의 고정 id(이 예제는 `crypto.randomUUID()`)
- **비권장(임시 예외)**: 배열 인덱스를 `key`로 쓰는 것은 순서가 바뀌기 쉬운 리스트에서 위험할 수 있습니다

## `filter`로 삭제하는 패턴

```js
setMenuItems((prev) => prev.filter((item) => item.id !== id))
```

- “불변성”을 지키기 위해, 보통 **새 배열을 만들어** 교체합니다(기존 배열을 직접 mutate하지 않음)

# 7강 — 백엔드 뼈대 + PostgreSQL + 사용자(User) 저장

## 이번 강의에서 배우는 것

- Spring Boot 프로젝트가 **어떻게 실행되어 HTTP 요청을 받는지**
- **PostgreSQL**에 연결하고, **JPA(Hibernate)**로 테이블과 자바 객체를 매핑하는 기본
- 비밀번호를 **평문으로 저장하지 않고 BCrypt 해시만 저장**하는 이유
- 앱 기동 시 DB가 비어 있으면 관리자 1명을 넣는 **시드(seed)** 패턴
- (검증용) REST로 **헬스 체크**와 **사용자 목록(JSON)**을 받아 본다

## 선행 조건

- **Java 기본**: 클래스, 생성자, 인터페이스를 읽을 수 있을 것
- **터미널**: 디렉터리 이동, 명령 실행
- **HTTP 기본**: `GET`이 무엇인지, 브라우저 주소창과의 대응
- (선택) **Docker**: `docker compose`로 컨테이너를 띄워 본 경험이 있으면 편하다

이 강의는 **React(1~6강)와 별도**이며, **프론트엔드 코드는 포함하지 않는다.**

## 개발 환경 (JDK·Maven) — 백엔드 강의 공통

7강부터 Maven(`mvn`)으로 Spring Boot를 띄운다. **처음 한 번만** 아래를 점검하면 8~13·15강(백엔드 Maven 프로젝트)에서도 같은 전제를 쓸 수 있다.

### 왜 `pom.xml`에는 Java 17인가

- **Spring Boot 3.x**는 **Java 17 이상**이 필요하다.
- 이 시리즈는 **강의 재현**과 **LTS(장기 지원)** 관점에서 **17**을 문서 기준으로 적어 두었다.
- PC에 **21, 25** 등 더 새 JDK만 있어도 **대부분 그대로 빌드·실행**된다. 다만 `mvn -v`에 나오는 **Java version**이 너무 다르면, 질문·스크린샷을 맞추기 어려울 수 있어 **17 또는 21 LTS**를 권장한다.

### 설치 여부 확인

```bash
java -version
javac -version
mvn -v
```

- `mvn -v` 출력에 **Apache Maven**과 **Java version**이 함께 보이면 된다. Maven이 잡는 JDK는 보통 **`JAVA_HOME`** 이 가리키는 것이다.

### Maven이 없을 때 (macOS 예: Homebrew)

```bash
brew install maven
```

### Homebrew로 Maven만 설치했을 때 — JDK 25와 17 (수업에서 헷갈리지 않기)

- Homebrew는 Maven과 함께 **최신 OpenJDK**(예: **25**)를 의존 패키지로 깔 수 있다. 그러면 터미널에서 **`java -version`** 과 **`mvn -v`** 에 나오는 **Java version**이 **25**로 보일 수 있다.
- 이 시리즈의 `pom.xml` 은 **`java.version` 17** 으로 두었고, Spring Boot 3.x 는 **17 이상**이면 빌드·실행이 가능하다. 그래서 **실제로는 JDK 25로 `mvn compile`·`mvn spring-boot:run` 이 성공하는 경우가 많다** — “25라서 안 된다”가 아니라, **강의 화면·질문을 17과 맞추려면** 아래처럼 **17을 쓰면 된다**.
- **`mvn`이 어떤 JDK를 쓰는지**는 거의 항상 **`JAVA_HOME`** 이 결정한다. 17을 깔았다면(`brew install openjdk@17` 등), 아래 **「JDK를 17에 맞추고 싶을 때」** 를 적용한 뒤 **`mvn -v`** 로 **Java version 이 17** 인지 확인하면 수업이 끊기지 않는다.

### JDK를 17에 맞추고 싶을 때 (선택)

시스템 기본이 25 등으로만 잡혀 있다면, Homebrew로 17을 깐 뒤 해당 세션에서:

```bash
brew install openjdk@17
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
java -version
mvn -v
```

`mvn -v` 의 **Java version** 이 **17** 으로 나오면, Maven도 같은 JDK로 동작하는 것이다.  
영구 반영은 셸 설정 파일(`~/.zshrc` 등)에 `export JAVA_HOME=...` 을 넣는 방식으로 한다(환경마다 다름).

### Maven 컴파일 **전**과 **후** 폴더 모습 (카피 프로젝트로 따라올 때)

강의 저장소에서 **소스만** 가져왔거나, `mvn clean` 으로 정리한 직후에는 아래처럼 **`target/` 이 없거나 비어 있는 것이 정상**이다. 저장소 **루트**의 `.gitignore` 에 **`target/`** 이 있어, Git 으로 받은 프로젝트에는 보통 **빌드 결과물이 포함되지 않는다**.

**컴파일하기 전(소스만 있는 상태 — 예시)**

```
lesson-07-spring-db-user/    ← Maven 프로젝트 루트(8~13강·15강 backend 도 같은 패턴)
  pom.xml
  src/
    main/
      java/
      resources/
  (target/ 없음)
```

**`mvn compile` 또는 `mvn spring-boot:run` / `mvn package` 를 한 번 실행한 뒤**

Maven이 **`target/`** 을 만들고, 그 안에 컴파일 산출물을 둔다. 이름만 알아 두면 “내 폴더에 갑자기 생긴 것”이 무엇인지 안심할 수 있다.

```
lesson-07-spring-db-user/
  pom.xml
  src/
    ...
  target/
    classes/                 ← .java 가 컴파일된 .class 와 리소스 복사본
    generated-sources/       ← (환경·버전에 따라 생길 수 있음)
    maven-status/          ← 컴파일러 플러그인 메타데이터
    test-classes/          ← `mvn test` 를 돌렸을 때 생김(생략된 경우도 있음)
```

- **`target/`** = **로컬에서 Maven이 만든 작업 폴더**이다. 지워도 되고, 다음 `mvn` 때 다시 생긴다.
- 정리하고 싶을 때: 프로젝트 루트에서 **`mvn clean`** → `target/` 삭제 후, 다음 빌드 때 다시 생성된다.
- **수강생이 따라올 때**: “저장소를 복제했는데 `target` 이 없다”는 것은 **오류가 아니라** 첫 `mvn` 전의 정상 상태다. 터미널에서 한 번 **`mvn -DskipTests compile`** 이라도 실행해 보면 `target/classes` 가 생기는지 확인할 수 있다.

### 8~15강과의 관계

같은 방식으로 **`mvn spring-boot:run`**, **`mvn -DskipTests package`** 를 쓴다. **상세한 JDK 문맥은 이 절을 기준**으로 하고, 8·9·15강 `강의.md`에는 필요 시 **「7강 개발 환경 절 참고」** 정도만 중복한다.

## 왜 이 단계가 필요한가

1~6강까지는 데이터가 **브라우저의 `localStorage`** 또는 **메모리(state)**에 머무는 경우가 많았습니다.  
이제부터는 **서버가 데이터의 진실(source of truth)을 갖고**, 나중에 **같은 데이터를 여러 클라이언트가 공유**할 수 있게 됩니다.

7강에서는 아직 **로그인 API(JWT 등)**까지 가지 않습니다.  
**“DB에 사용자 행이 생기고, API로 그 사실을 확인한다”**에 집중하면 다음 강(인증)으로 넘어가기 쉽습니다.

## 새로 등장하는 용어 (짧게)

| 용어 | 한 줄 설명 |
|------|------------|
| **Spring Boot** | 스프링 기반 앱을 빠르게 만들기 위한 실행·설정 도우미 묶음 |
| **JPA** | 자바 객체 ↔ 관계형 테이블 매핑을 표준 API로 다루는 방식(구현체로 Hibernate가 많이 쓰임) |
| **엔티티** | DB 테이블과 1:1로 대응하는 자바 클래스(이 강의에서는 `User`) |
| **Repository** | 테이블에 `save`, `findAll` 등을 호출하는 계층(Spring Data가 구현체 생성) |
| **BCrypt** | 비밀번호를 **해시**로 바꿔 저장할 때 자주 쓰는 알고리즘 계열 |
| **시드(seed)** | 최초 데이터를 코드로 넣어 두는 것(관리자 계정 등) |

## 따라 하기 (단계별)

### 1) 저장소 위치로 이동

터미널에서 이 폴더(`lesson-07-spring-db-user`)로 이동합니다.

### 2) JDK·Maven 확인

위 **「개발 환경 (JDK·Maven)」** 절에서 `java -version` / `mvn -v` 를 확인한다.  
IDE만 쓸 경우에도, 터미널에서 같은 명령이 통과하는지 보면 스크린샷·질문이 수월하다.

### 3) PostgreSQL 기동 (Docker 사용 시)

```bash
docker compose up -d
```

이미 로컬에 같은 포트(5432)로 Postgres가 떠 있으면 **충돌**합니다. 그 경우:

- Docker Compose의 포트 매핑을 바꾸거나,
- `application.yml`의 JDBC URL 포트를 로컬 인스턴스에 맞추면 됩니다.

### 4) 애플리케이션 실행

```bash
mvn spring-boot:run
```

처음 실행 시 Maven이 의존성을 받아 오므로 **시간이 걸릴 수 있습니다.**

### 5) 헬스 체크

브라우저나 `curl`로:

```text
GET http://localhost:8080/api/health
```

JSON에 `"status":"ok"`가 보이면 **웹 계층은 정상**입니다.

### 6) 사용자 목록

```text
GET http://localhost:8080/api/users
```

시드가 성공했다면 **관리자 한 명**이 보입니다.  
응답에는 **`passwordHash`가 포함되지 않습니다.** 의도적으로 DTO(`UserResponse`)로 막았습니다.

### 7) DB에 실제로 들어갔는지 보기 (선택)

- Docker로 띄웠다면 `docker exec`로 `psql`에 들어가 `beanlog_users` 테이블을 조회하거나,
- DBeaver·DataGrip 같은 클라이언트로 `jdbc:postgresql://localhost:5432/beanlog_lesson07`에 접속합니다.

`password_hash` 컬럼에 **긴 무작위 같은 문자열**이 있으면 BCrypt 해시가 저장된 것입니다.

## 설정 파일 읽기 (`application.yml`)

- **`spring.jpa.hibernate.ddl-auto: update`**  
  개발 편의를 위해 **엔티티에 맞춰 테이블을 자동 생성/갱신**합니다.  
  **운영 환경**에서는 보통 `validate`나 마이그레이션 도구(Flyway 등)를 쓰고, 함부로 `update`를 쓰지 않습니다.
- **환경 변수로 덮어쓰기**  
  `SPRING_DATASOURCE_URL` 등은 배포 시 비밀을 코드에 넣지 않기 위한 관례입니다.

## 시드 비밀번호는 어디에 적혀 있나

`AdminUserSeeder`에 상수로 있습니다. **평문은 DB에 저장되지 않고**, BCrypt로 바꾼 값만 저장됩니다.  
8강에서 로그인을 구현할 때, 사용자가 입력한 평문과 `BCrypt.matches`로 비교하게 됩니다.

## 막혔을 때 (자주 나는 오류)

| 증상 | 점검할 것 |
|------|-----------|
| DB 연결 거부 | Postgres가 떠 있는지, URL·포트·DB 이름이 `application.yml`과 같은지 |
| 포트 8080 사용 중 | 다른 프로그램 종료 또는 `SERVER_PORT=8081` 등으로 변경 후 실행 |
| 테이블이 안 생김 | 로그에 JPA/Hibernate 에러가 없는지, `ddl-auto`가 `none`으로 바뀌지 않았는지 |
| 시드가 안 들어감 | 이미 사용자가 있으면 시드는 건너뜀 → DB를 비우고 다시 실행해 본다 |

## 보안에 대한 짧은 주의

- 이 강의의 `/api/users`는 **인증 없이 열려 있다.** 학습용으로만 쓰고, 실제 서비스에서는 **관리자만** 보도록 막는다.
- **절대** Git에 DB 비밀번호·운영 키를 커밋하지 않는다.
